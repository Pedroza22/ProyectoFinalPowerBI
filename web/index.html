Contexto

2. Problema, objetivo y alcance

Problema que se aborda

La información de rendimiento, ausencias y actividad en plataformas educativas puede ser difícil de interpretar cuando se encuentra en registros separados o en tablas sin análisis integrado. Esto limita la identificación de patrones, diferencias entre grupos y señales que ameritan seguimiento.

Objetivo general

Implementar un flujo de análisis de datos que integre ETL, modelado semántico, visualización en Power BI y validación estadística para explorar el rendimiento estudiantil y los factores asociados.

Objetivos específicos

  • Preparar y organizar los registros del conjunto de datos educativo.
  • Construir un modelo dimensional que facilite el análisis por diferentes categorías.
  • Crear medidas DAX para indicadores, comparaciones, rankings y asociaciones.
  • Responder diez preguntas de análisis mediante visualizaciones del dashboard.
  • Complementar el análisis descriptivo con pruebas estadísticas e interpretación de resultados.

4. Proceso ETL: extracción, transformación y carga

E · Extract

Extracción

Lectura de xAPI-Edu-Data.csv con pandas.read_csv(). Validación de 17 columnas, nulos y duplicados.

T · Transform

Transformación

Limpieza, renombrado al español, campos derivados e indicadores calculados en Python.

L · Load

Carga

8 CSV en datos/modelo_estrella/ para Power BI. Carga opcional en PostgreSQL vía Docker.

Script: scripts/01_etl.py

FunciónQué hace
extraer(ruta)Lee el CSV, valida las 17 columnas esperadas, aborta si falta alguna.
calidad(df)Reporta nulos, duplicados exactos y rangos fuera de escala (0–100).
transformar(df)Limpia texto, renombra columnas, mapea códigos y calcula campos derivados.
cargar(df, carpeta)Genera 7 dimensiones y Fact_Desempeno.csv con claves surrogadas (SK_*).

Transformaciones aplicadas

  • Nota_Ordinal: Bajo=1, Medio=2, Alto=3 — para ordenar niveles en gráficos.
  • Nota_Aproximada: Bajo=60, Medio=80, Alto=95 — punto medio de cada banda.
  • Es_Reprobado / Es_Sobresaliente / Es_Riesgo_Desercion: flags binarios con np.where.
  • Indice_Participacion: promedio de las 4 métricas de actividad LMS.
  • Rango_Participacion: intervalos 0–25, 26–50, 51–75, 76–100 con pd.cut().

¿Por qué Power BI usa CSV y no PostgreSQL? Power BI Service requiere un Data Gateway para conectarse a una base de datos local. Para el despliegue público se usaron CSV directamente. La BD existe y está documentada como evidencia del componente de carga.

13. Limitaciones y mejoras recomendadas

  1. Fuente escolar: el dataset no es de universidades reales; describir como análisis de datos educativos adaptados.
  2. Nota proxy: 60/80/95 no son calificaciones reales; rotular siempre como "puntaje aproximado".
  3. Deserción proxy: no es tasa real; para medir abandono se requieren registros de retiro.
  4. Comparación semestral: son grupos distintos, no evolución individual de los mismos estudiantes.
  5. Grupos pequeños: Grado 05 tiene 3 estudiantes; Sección C tiene 30. Rankings con cautela.
  6. p-valores en CSV: valores muy pequeños guardados como 0.0; mostrar como "p < 0.001".
  7. ANOVA estática: la tabla no responde a filtros; corresponde a la muestra global.
  8. Ruta de datos: el PBIX usa ruta absoluta local; cambiar a ruta relativa o SharePoint para compartir.
